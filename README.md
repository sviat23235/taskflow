## Вибір моделі життєвого циклу: Agile (Scrum)
Для TaskFlow обрано Scrum зі спринтом 1 тиждень. Вимоги до невеликого застосунку можуть уточнюватися по ходу роботи, а короткі ітерації дають робочий інкремент щотижня й дозволяють швидко отримувати зворотний зв'язок. Waterfall відхилено: він погано витримує зміну вимог і відкладає тестування на кінець. V-model надмірно формальна для проєкту такого масштабу.

**Артефакти:** product backlog (список усіх фіч із пріоритетами), sprint backlog (завдання поточного спринту), інкремент (працююча версія), Definition of Done (код змерджено в `develop`, тести пройдено, review виконано, документацію та CHANGELOG оновлено).

**Розклад ітерації:** планування спринту (понеділок, до 1 год), короткі щоденні синхронізації (або самоперевірка при роботі наодинці), sprint review із демонстрацією результату (п'ятниця), ретроспектива (15–30 хв після review).

**Ризики:** розповзання обсягу (мітигація — чіткий backlog і пріоритети), нестача часу (мітигація — розбиття фіч на малі завдання), регресії (мітигація — автотести та CI).

Версіонування й Git-процес описано у `VERSIONING.md`.
